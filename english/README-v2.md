# 영어 V2 12주 보드

`v2.html`을 기존 정적 서버에서 열면 됩니다. V1과 메인 보드 저장 키는 사용하지 않습니다.

## 기록 보존

- 저장 키는 `heeyoon-english-board:v2`를 유지합니다.
- version 1의 sessions는 그대로 weeks["1"].sessions로 이동합니다.
- 이동 전에 원문을 `heeyoon-english-board:v2:pre-weeks-backup`에 한 번만 보관합니다. 기존 백업은 덮어쓰지 않습니다.
- 완료 세션은 읽기 전용으로 다시 볼 수 있습니다. 기록과 완료일을 초기화하지 않습니다.
- 잘못된 JSON은 초기화하지 않고 안내를 표시합니다.

## 가족 동기화 사용 순서

1. 기존 `anonymous-family.sql`의 가족 설정이 있는 Supabase 프로젝트에 `supabase/english-progress.sql`을 직접 실행합니다. 이번 개발에서는 실행하지 않았습니다.
2. **희윤컴**의 영어 V2 부모 기록에서 JSON 백업을 다운로드합니다.
3. 읽기 전용 비교로 이 기기/클라우드 세션 수와 신규·동일·충돌을 확인합니다.
4. `이전하기`를 누르면 없는 세션만 INSERT합니다. 동일 세션은 연결하고, 다른 값은 보류합니다.
5. 그램에서 열기·새로고침·화면 복귀 시 클라우드 기록을 받습니다. 그램의 기존 부분 기록과 충돌하면 양쪽 원본을 보존하고 보류합니다. **그램에서 먼저 이전하지 마세요.**

새 학습 변경은 로컬 저장 → 전용 재시도 큐 → 인증 준비 → 클라우드 전송 순서입니다. 실패한 큐는 보존합니다. 새 세션은 자동 동기화하며, 이전 대기 중인 기존 세션의 변경은 명시적 이전 전까지 전송하지 않습니다.

같은 세션을 두 기기에서 다르게 바꾸면 마지막 기록으로 덮어쓰지 않습니다. 알려진 revision에 대한 조건부 UPDATE로 전송하고, 경쟁 쓰기나 기존 값 차이는 `충돌 보류`로 표시합니다. 보류된 기록은 백업해 두고 부모가 확인해야 합니다. 이번 버전은 충돌 기록의 자동 병합이나 임의 강제 덮어쓰기를 제공하지 않습니다.

SDK의 기존 anonymous 인증 저장 키와 `heeyoon_family_owner()` RPC를 재사용합니다. 영어 전용 테이블 외에는 접근하지 않습니다. 60초마다, 온라인 복귀와 화면 복귀 때 재연결합니다. SQL의 revision trigger와 RLS는 파일로 제공했으며 실제 DB 동작은 이번 작업 범위에서 검증하지 않았습니다.

## 검증

```
node scripts/test-english-v2-cloud.cjs
node scripts/serve.cjs
node scripts/test-english-v2.cjs
git diff --check
```

브라우저 검증에는 Playwright와 Edge가 필요합니다. 브라우저 테스트는 SDK를 mock으로 대체하고 모든 외부 요청을 차단합니다. 기존 사용자 브라우저나 실제 Supabase 기록에는 접근하지 않습니다. 미리보기 저장 경로는 `ENGLISH_V2_PREVIEW_DIR`로 지정할 수 있습니다.
